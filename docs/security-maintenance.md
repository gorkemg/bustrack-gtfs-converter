# Security maintenance

The `security-check` job runs the standard-library unit tests on pull requests, pushes to main, daily and on demand. It uses a read-only token and does not publish releases. This is a test suite, not a static vulnerability scanner or a guarantee that feeds are safe. Dependabot checks GitHub Actions daily; there are no Python dependency manifests to monitor. Review proposed action updates and verify the upstream commit before merging.

The release workflow fails on converter errors and publishes only after checking the generated ZIP's expected single regular entry, size, SQLite integrity, agency metadata, schema version and core table presence and non-emptiness. An explicit unchanged result skips publication. This does not establish provenance or semantic correctness of upstream GTFS data. Release operations are separate GitHub API calls and are not atomic: a later failure may leave an archive or previous release updated without updating production.

The upstream download/extraction pipeline remains outside this change. Its downloads and ZIP extraction do not impose compressed or expanded size limits, and the external PVTA route details endpoint uses HTTP. Consider bounded downloads, strict input archive validation, source authentication, and HTTPS when the upstream supports it. The release check also falls back to downloading when metadata checks fail; cache and source metadata are not authenticity guarantees. Rollback restores a previously published asset and does not revalidate it here.
